## Applied Work Units

### Runner persistence barrier

- Ported the Java `PersistBarrier` behavior for the sequential tool execution race.
- Added invocation-scoped shared scratch state via `InvocationContext.callbackContextData`.
- Runner now marks persisted or failed event IDs after `sessionService.appendEvent`.
- `BaseLlmFlow.runAsync` waits for each step's emitted events to be persisted before building the next request.
- Plugin-modified events are handled by resolving both the original flow event ID and the persisted output event ID.

### Request input tool

- Added public `RequestInputTool` and default `requestInput` instance.
- Exposes the upstream `adk_request_input` function declaration with `message` and optional `response_schema`.
- Marks the tool as long-running and exports it through `adk_dart.dart` and `adk_core.dart`.

### Session user state and event retrieval parity

- Added `BaseSessionService.getUserState(appName, userId)` to match the latest Python session API.
- Implemented raw user-scoped state lookup for in-memory, SQLite, network database, and URL-dispatched database services.
- Marked `VertexAiSessionService.getUserState` unsupported because Vertex AI does not expose user state independently of a session.
- Fixed `GetSessionConfig(numRecentEvents: 0)` to return an empty event list instead of all events across in-memory, SQLite, network database, and Vertex session services.

### Task-mode finish task parity

- Added Python-compatible `FinishTaskTool` with the `finish_task` function name and task completion instruction.
- Added default task output schema behavior plus JSON-schema based output validation for object, primitive, array, enum, `anyOf`, and `oneOf` schemas.
- Added `TaskRequest` and `TaskResult` data models with Python-compatible JSON keys.
- Added `LlmAgent.mode` support and auto-installs `finish_task` when `mode: task`.
- Added `mode` parsing/serialization for `LlmAgentConfig`.
- Skipped generic `output_schema` and `set_model_response` processing for task-mode agents so structured task output goes through `finish_task`, matching Python.

### Single-turn identity parity

- Matched Python's identity request processor behavior by omitting framework-generated agent identity instructions when `LlmAgent.mode == 'single_turn'`.
- Added a flow-level regression test to verify `single_turn` keeps global/static instructions while removing the internal-name identity prompt.

### Task/single-turn transfer target parity

- Matched Python's transfer processor behavior by excluding `task` and `single_turn` agents from normal `transfer_to_agent` targets.
- Skipped transfer instruction text for current agents running in `task` or `single_turn` mode while keeping the transfer tool path available for normal targets.
- Added transfer-target regression tests for child and peer filtering.

### Task/single-turn sub-agent wrapper parity

- Added public `SingleTurnAgentTool` and `TaskAgentTool` wrappers matching the latest Python sub-agent mode registration model.
- `LlmAgent` now defaults LLM sub-agents with no `mode` to `chat` and automatically exposes `single_turn` and `task` sub-agents as tools.
- `TaskAgentTool` now emits the Python-compatible default `request` schema and no-parallel delegation instruction, while preserving a task sub-agent's custom input schema when present.
- Clone handling now removes generated sub-agent wrappers that point at the source tree and reinstalls wrappers against cloned sub-agents.

### Deferred tool response parity

- Added `BaseTool.defersResponse` to mirror Python's internal `_defers_response` marker.
- `TaskAgentTool` now sets `defersResponse` so the framework can distinguish task delegation markers from ordinary tools.
- Function-call processing now skips automatic function response event creation when a long-running or deferred-response tool returns an empty response, matching Python's function processor behavior.
- Toolset name-prefix wrappers now preserve `defersResponse` when wrapping tools.

### Event isolation scope foundation

- Added `Event.isolationScope` as the Dart-side foundation for Python's task delegation isolation mechanism.
- Runner output-event merging now preserves isolation scope across plugin-modified events.
- SQLite session event JSON, local storage schema v0/v1 event data, and Vertex AI event metadata now persist and restore isolation scope.
- Added unit and persistence tests for event copy, storage event data round-trip, SQLite round-trip, and Vertex AI injected-client round-trip.

### Scoped task content filtering parity

- Added `InvocationContext.isolationScope` and copy support so scoped task execution can carry the same logical conversation scope as Python ADK.
- Updated LLM content assembly to include only events whose `Event.isolationScope` exactly matches the active invocation scope.
- Added task-input reconstruction from the originating function-call arguments, including the single-turn no-clarification nudge used by Python.
- Guarded the base LLM flow fallback content path so scoped contexts cannot leak unscoped or differently scoped session history.
- Scoped agent execution now stamps emitted agent events, state events, runner user events, live appended user content, and runner early-exit events with the active isolation scope when one is present.
- Added regression tests for context copy behavior and scoped content/task-input reconstruction.

### Inline task/single-turn dispatch bridge

- Replaced the task-mode wrapper marker-only behavior with same-session child-agent execution for `TaskAgentTool`.
- Added same-session execution for `SingleTurnAgentTool`, including a child branch (`parent.child`) and a synthetic user event in the parent session.
- Task-mode execution now runs child events with `isolationScope == functionCallId`, appends those events to the parent session, and marks `PersistBarrier` IDs after append so multi-step child flows can advance.
- `TaskAgentTool` now detects successful `finish_task` function responses and returns the pending `finish_task` args as object output, or unwraps `result` for primitive output schemas.
- Tool-level plugin event callbacks and child state deltas are propagated during inline execution, while `includePlugins: false` disables inherited plugins for wrapper dispatch.

### Skill toolset latest parity

- Added `SkillToolset` constructor support for `toolNamePrefix` and `toolFilter`, matching the current upstream toolset contract.
- Updated skill system instructions to be prefix-aware and to include the latest Python guidance for skill-bundled resources and no-retry behavior after `load_skill_resource` errors.
- Added the invocation-scoped repeated resource lookup guard: the first missing resource returns `RESOURCE_NOT_FOUND`, subsequent misses in the same invocation return `RESOURCE_NOT_FOUND_FATAL`.
- Added skill-tool error-code detection so telemetry/callback consumers can classify `error_code` responses from search/load/resource/script tools.

### BigQuery analytics GCS offload

- Connected `BigQueryLoggerConfig.gcsBucketName` to actual GCS offload behavior.
- Added injectable `BigQueryGcsUploadProvider` for tests and custom runtimes.
- Added a default Cloud Storage JSON upload path using OAuth access tokens.
- Converted `content_parts` to the upstream-style schema with `part_index`, `storage_mode`, `uri`, `object_ref`, and `part_attributes`.
- Inline media and large text can now become `GCS_REFERENCE` rows with `gs://` URIs and GCS metadata.
- Added config override support for `gcs_bucket_name` and `connection_id`.

### Auto tracing plugin parity

- Added `AutoTracingPlugin` to reduce the latest Python `auto_tracing_plugin` gap through Dart plugin hooks.
- Records invocation, agent, model, and tool spans with existing `gen_ai.*` and `gcp.vertex.agent.*` telemetry attributes.
- Captures bounded request, response, tool argument, return, and exception summaries.
- Added cleanup handling for short-circuited callback paths, such as a model response returned from `beforeModelCallback` where no `afterModelCallback` is invoked.
- Added `AdkTracer.endSpan(span)` so plugins can close a specific active span and safely unwind leaked nested spans.

### Shared plugin close ownership parity

- Added `PluginManager.setSkipClosingPlugins(bool)` to match Python's latest shared-plugin ownership guard.
- `PluginManager.close()` now becomes a no-op when the manager references plugin instances owned by another runner.
- Fixed `AgentTool(includePlugins: true)` so the child runner can inherit parent plugin callbacks without closing the parent plugin instances when child execution finishes.
- Added a regression test that would previously close an inherited parent plugin through `AgentTool.run`.

### Invocation abort signal parity

- Added public `AdkAbortController`, `AdkAbortSignal`, and `AdkAbortException` primitives for cooperative invocation cancellation.
- Exposed the active abort signal through `InvocationContext`, `ReadonlyContext`, and therefore tool/callback contexts.
- Added optional `abortSignal` parameters to `Runner.run`, `Runner.runAsync`, and `Runner.runLive`.
- Propagated abort checks through runner setup, user-message plugin processing, before-run, event plugin processing, session append, yield, and after-run boundaries.
- Added abort-aware exits in `BaseAgent`, `LlmAgent`, `LoopAgent`, `ParallelAgent`, LLM flow processing, function-call processing, and `AgentTool` child/inline runner paths.
- Added regression coverage for pre-aborted runs, user-message plugin aborts before user-event append, and event plugin aborts before model-event append/yield.

### Dev server client-disconnect abort parity

- Wired `/run_sse` to create an invocation abort signal and pass it into `Runner.runAsync`.
- Aborts the SSE invocation when writing or flushing to the client fails, and avoids sending a trailing error frame to a disconnected client.
- Wired `/run_live` to create an invocation abort signal and pass it into `Runner.runLive`.
- Aborts live WebSocket invocations when either the event-forwarding task or socket-message task ends, then closes the live request queue.
- Added web server regression coverage proving `/run_sse` receives a live abort signal and `/run_live` marks that signal aborted after socket close.

### AgentTool temporary-state isolation regression

- Matched the latest JS regression coverage for parent `temp:` state isolation when `AgentTool` creates a child-agent session.
- Added a child-agent capture test proving ordinary parent state is visible in the child session while `temp:` entries are filtered before child execution.
- Confirmed this is already handled by Dart's shared `extractStateDelta` session creation path, so no runtime code change was required.

### Workflow retry exception-filter parity

- Aligned explicit workflow `RetryConfig` behavior with Python v2 defaults: nodes without retry config still run once, while nodes with retry config default to 5 attempts.
- Added `RetryConfig.exceptions` support for retry filtering by exception class name or exact Dart `Type`.
- Added regression coverage for default retry attempts, matching exception-name retries, and non-matching exception failures without retry.

### SSE streaming tool-call history parity

- Matched the latest JS streaming fix for non-progressive SSE session history.
- Non-progressive streaming now splits mixed text and tool-call chunks into separate saveable final events instead of dropping tool calls when text appears first.
- Buffered text is flushed before non-text parts, including tool calls, so function-call events are preserved without relying on `close()` replay.
- Empty `STOP` content chunks emitted after a function call are suppressed while preserving usage and grounding metadata for the final aggregated response.
- Added regression coverage for mixed text/tool chunks, multiple tool calls, empty `STOP` suppression, and metadata preservation.

### SSE terminal frame parity

- Matched the latest Python streaming fix that guarantees `StreamingResponseAggregator.close()` returns a terminal `partial: false` response after any observed response.
- Empty-content responses now close with an empty terminal frame instead of `null` in both progressive and non-progressive SSE modes.
- Error-only responses now close with a terminal frame preserving `errorCode`, `errorMessage`, and usage metadata.
- Non-progressive pure function-call streams still emit function-call events during processing, and now additionally close with an empty terminal frame so clients waiting for completion do not hang.
- Added regression coverage for empty content, error-only final frames, and updated non-progressive function-call close behavior.

### Tool execution mode parity

- Added `ToolExecutionMode` to `RunConfig`, matching the latest Java control surface for multiple tool calls.
- Added `none`, `sequential`, `parallel`, and `parallelSubscribe` values. `none`, `parallel`, and `parallelSubscribe` preserve Dart's existing eager parallel behavior.
- Updated function-call execution so `ToolExecutionMode.sequential` awaits each requested tool in model order before starting the next one.
- Added regression coverage proving default parallel execution can complete faster tools first, while sequential mode preserves start and finish order.

### Nullable function schema parity

- Matched the latest Java nullable schema validation behavior for Dart task output schema validation.
- `FinishTaskTool` now accepts `null` only when the field schema has `nullable: true` or a `type` union containing `null`.
- Non-nullable `null` values still fail type validation, preserving existing strict output validation behavior.
- Updated public function-parameter schema parsing so nullable union annotations such as `[String, 'null']` are preserved as JSON-schema type unions.
- Added regression coverage for nullable task output fields, non-nullable null rejection, `type: ['string', 'null']`, and nullable parameter schema inference.

### A2A required-state mock call parity

- Matched the latest Python A2A conversion behavior that distinguishes input-required and auth-required synthetic function calls.
- `inputRequired` still uses `mock_function_call_for_required_user_input` with an `input_required` args key.
- `authRequired` now uses `mock_function_call_for_required_user_auth` with an `auth_required` args key instead of reusing the input-required mock.
- `RemoteA2aAgent` now converts user function responses for both mock function names back into user text before sending the resume request to the remote A2A peer.
- Added regression coverage for input/auth args separation and auth-required mock function-response resume.

- Full `dart analyze` still fails outside `lib/test` because workspace-local packages and Flutter example dependencies are unresolved under the current package root.
- Python v2 workflow deep parity is not complete: routed edges, `Event(output)`, `NodeInfo` event metadata, request-input event helper baseline, waiting interrupt state, standalone workflow resume baseline, workflow resume route preservation, workflow `max_concurrency`, dynamic `runNode` execution/resume/dedup baseline, explicit dynamic `runId` baseline, direct context result-channel baseline, CLI graph serialization baseline, Python-style app-info graph field, dev-server graph app-info fallback, app graph route baseline, build_graph_image response baseline, nested workflow graph-image selection, and workflow graph visualization baseline are now covered, but cross-turn event rehydration, full dynamic scheduler parity for auto-generated multiple same-name instances and parallel output delegation, full task/chat LLM-agent wrapper semantics, replay utilities, and rich graph visualization status/style/image rendering still need a dedicated pass.
- Python task delegation core dispatch is now present for task/single-turn mode wrappers. Remaining parity work is the broader Python v2 workflow scheduler/resume surface around `run_node`, not the basic wrapper dispatch path.
- Python `AutoTracingPlugin` monkey-patches arbitrary Python functions. Dart now has hook-based auto tracing for ADK lifecycle spans, but arbitrary function monkey-patching is not a Dart runtime capability.
- Some cloud service defaults remain injection-based or partial, including default BigQuery/Bigtable/Spanner clients, Vertex AI remote session persistence, and live cloud E2E coverage.
