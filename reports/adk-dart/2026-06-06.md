## Applied Work Units

### Runner persistence barrier

- Ported the Java `PersistBarrier` behavior for the sequential tool execution race.
- Added invocation-scoped shared scratch state via `InvocationContext.callbackContextData`.
- Runner now marks persisted or failed event IDs after `sessionService.appendEvent`.
- `BaseLlmFlow.runAsync` waits for each step's emitted events to be persisted before building the next request.
- Plugin-modified events are handled by resolving both the original flow event ID and the persisted output event ID.

### Request input tool

- Added public `RequestInputTool` and default `requestInput` instance.
- Exposes the upstream `adk_request_input` function declaration with `message` and optional `response_schema`.
- Marks the tool as long-running and exports it through `adk_dart.dart` and `adk_core.dart`.

### Session user state and event retrieval parity

- Added `BaseSessionService.getUserState(appName, userId)` to match the latest Python session API.
- Implemented raw user-scoped state lookup for in-memory, SQLite, network database, and URL-dispatched database services.
- Marked `VertexAiSessionService.getUserState` unsupported because Vertex AI does not expose user state independently of a session.
- Fixed `GetSessionConfig(numRecentEvents: 0)` to return an empty event list instead of all events across in-memory, SQLite, network database, and Vertex session services.

### Task-mode finish task parity

- Added Python-compatible `FinishTaskTool` with the `finish_task` function name and task completion instruction.
- Added default task output schema behavior plus JSON-schema based output validation for object, primitive, array, enum, `anyOf`, and `oneOf` schemas.
- Added `TaskRequest` and `TaskResult` data models with Python-compatible JSON keys.
- Added `LlmAgent.mode` support and auto-installs `finish_task` when `mode: task`.
- Added `mode` parsing/serialization for `LlmAgentConfig`.
- Skipped generic `output_schema` and `set_model_response` processing for task-mode agents so structured task output goes through `finish_task`, matching Python.

### Single-turn identity parity

- Matched Python's identity request processor behavior by omitting framework-generated agent identity instructions when `LlmAgent.mode == 'single_turn'`.
- Added a flow-level regression test to verify `single_turn` keeps global/static instructions while removing the internal-name identity prompt.

### Task/single-turn transfer target parity

- Matched Python's transfer processor behavior by excluding `task` and `single_turn` agents from normal `transfer_to_agent` targets.
- Skipped transfer instruction text for current agents running in `task` or `single_turn` mode while keeping the transfer tool path available for normal targets.
- Added transfer-target regression tests for child and peer filtering.

### Task/single-turn sub-agent wrapper parity

- Added public `SingleTurnAgentTool` and `TaskAgentTool` wrappers matching the latest Python sub-agent mode registration model.
- `LlmAgent` now defaults LLM sub-agents with no `mode` to `chat` and automatically exposes `single_turn` and `task` sub-agents as tools.
- `TaskAgentTool` now emits the Python-compatible default `request` schema and no-parallel delegation instruction, while preserving a task sub-agent's custom input schema when present.
- Clone handling now removes generated sub-agent wrappers that point at the source tree and reinstalls wrappers against cloned sub-agents.

### Deferred tool response parity

- Added `BaseTool.defersResponse` to mirror Python's internal `_defers_response` marker.
- `TaskAgentTool` now sets `defersResponse` so the framework can distinguish task delegation markers from ordinary tools.
- Function-call processing now skips automatic function response event creation when a long-running or deferred-response tool returns an empty response, matching Python's function processor behavior.
- Toolset name-prefix wrappers now preserve `defersResponse` when wrapping tools.

### Event isolation scope foundation

- Added `Event.isolationScope` as the Dart-side foundation for Python's task delegation isolation mechanism.
- Runner output-event merging now preserves isolation scope across plugin-modified events.
- SQLite session event JSON, local storage schema v0/v1 event data, and Vertex AI event metadata now persist and restore isolation scope.
- Added unit and persistence tests for event copy, storage event data round-trip, SQLite round-trip, and Vertex AI injected-client round-trip.

### Scoped task content filtering parity

- Added `InvocationContext.isolationScope` and copy support so scoped task execution can carry the same logical conversation scope as Python ADK.
- Updated LLM content assembly to include only events whose `Event.isolationScope` exactly matches the active invocation scope.
- Added task-input reconstruction from the originating function-call arguments, including the single-turn no-clarification nudge used by Python.
- Guarded the base LLM flow fallback content path so scoped contexts cannot leak unscoped or differently scoped session history.
- Scoped agent execution now stamps emitted agent events, state events, runner user events, live appended user content, and runner early-exit events with the active isolation scope when one is present.
- Added regression tests for context copy behavior and scoped content/task-input reconstruction.

### Inline task/single-turn dispatch bridge

- Replaced the task-mode wrapper marker-only behavior with same-session child-agent execution for `TaskAgentTool`.
- Added same-session execution for `SingleTurnAgentTool`, including a child branch (`parent.child`) and a synthetic user event in the parent session.
- Task-mode execution now runs child events with `isolationScope == functionCallId`, appends those events to the parent session, and marks `PersistBarrier` IDs after append so multi-step child flows can advance.
- `TaskAgentTool` now detects successful `finish_task` function responses and returns the pending `finish_task` args as object output, or unwraps `result` for primitive output schemas.
- Tool-level plugin event callbacks and child state deltas are propagated during inline execution, while `includePlugins: false` disables inherited plugins for wrapper dispatch.

### BigQuery analytics GCS offload

- Connected `BigQueryLoggerConfig.gcsBucketName` to actual GCS offload behavior.
- Added injectable `BigQueryGcsUploadProvider` for tests and custom runtimes.
- Added a default Cloud Storage JSON upload path using OAuth access tokens.
- Converted `content_parts` to the upstream-style schema with `part_index`, `storage_mode`, `uri`, `object_ref`, and `part_attributes`.
- Inline media and large text can now become `GCS_REFERENCE` rows with `gs://` URIs and GCS metadata.
- Added config override support for `gcs_bucket_name` and `connection_id`.
